## 0.1 为什么要有数据库？（先跟你熟悉的 Excel 对比）

| | Excel 表格 | 数据库（MySQL） |
|---|---|---|
| 谁在用 | 通常一个人 | **很多人、很多程序同时用** |
| 数据量 | 几万行就开始卡 | 几千万、几亿行也能快速查 |
| 多人同时改 | 会互相覆盖、起冲突 | 靠**事务**保证不打架（U2 会讲） |
| 权限 | 拿到文件就能全改 | 能精细到"只准看某几张表" |
| 出错了 | 靠自己回滚 | 有日志，能**恢复到某一秒** |
| 查数据 | 靠筛选、公式 | 靠 **SQL**：你只说"要什么"，不用管"怎么找" |

**一句话**：数据库 = **有规矩、能多人同时用、坏了还能恢复的数据仓库**。

## 0.2 「服务器」和「客户端」—— 你可能没意识到，你已经用过好几轮了

MySQL 其实分成两半：

| | 是什么 | 在你这台机器上是哪个 |
|---|---|---|
| **服务器** | 常驻后台的程序，真正干活、真正存数据 | 服务名 `MySQL267`（**正在运行**，来源：Windows 服务列表，我查的） |
| **客户端** | 你敲命令的小工具，负责**传话** | `mysql.exe`（来源：`C:\Program Files\MySQL\MySQL Server 26.7\bin\`） |

流程是这样：

```
你敲命令  →  客户端 mysql.exe  →（通过网络）→  服务器 MySQL267  →  执行
                                  ←（原路返回）←  结果
```

**你敲过的那条长命令，每个部分都有意思**：

```
mysql -h 127.0.0.1 -P 3306 -u root -p
      └────┬────┘ └──┬──┘ └──┬─┘ └┬┘
       服务器在哪   门牌号   你是谁  要输密码
```
- `-h 127.0.0.1` —— 服务器在哪。`127.0.0.1` 意思是"**本机**"（不是别的电脑）
- `-P 3306` —— 服务器的**端口**（门牌号）。一台机器上可以有很多服务，靠端口区分
- `-u root` —— 你以**哪个用户**登录
- `-p` —— 提示你输密码（**不写 `-p` = 用空密码登录**，这就是你之前那个 `using password: NO` 报错的由来）

**熟悉的类比**：浏览器（客户端）↔ 网站服务器。浏览器不存网页，它只是替你问服务器。

## 0.3 库 → 表 → 行 → 列 —— 一层一层装东西

```
服务器（MySQL267）
 └── 库 / database（也叫 schema）      ← 一套业务的容器
      └── 表 / table                  ← 一类东西的清单
           └── 行 / row（记录）        ← 一条具体数据
                └── 列 / column（字段） ← 这条数据的一个属性
```

**先看你已经有的库**（来源：**你跑的那条清点 SQL 的最后一张表**）：

| 库名 | 表数 | 属于谁 |
|---|---|---|
| `sakila` | 23 | MySQL 官方的**示例业务库**（一个租 DVD 的店） |
| `world` | 3 | MySQL 官方示例（国家/城市） |
| `practice` | 2 | **你自己建的练习库** |
| `mysql` / `information_schema` / `performance_schema` / `sys` | 38 / 84 / 117 / 101 | **MySQL 自己用的系统库** —— 别去改 |

> 前三个是"业务数据"，后四个是"数据库自己的零件仓库"。
> 你那条清点 SQL 就是去 `performance_schema`（性能档案室）里查服务器状态的。

**表长什么样**：就是一张二维表格

| actor_id | first_name | last_name | last_update |
|---|---|---|---|
| 1 | PENELOPE | GUINESS | 2006-02-15 04:34:33 |
| 2 | NICK | WAHLBERG | 2006-02-15 04:34:33 |

- **列**（表头）= 字段名 + 数据类型。这张表有 4 列
- **行** = 一条完整记录。上面有 2 行 = 2 个演员
- 行列交叉的那个格子叫**单元格**

`sakila` 里就有这么一张表叫 `actor`（演员表），你等会儿能亲眼看到。

## 0.4 数据类型：每一列必须声明"存什么"

你在建表时要告诉 MySQL 每列存什么，常用的几种：

| 类型 | 存什么 | 例子 |
|---|---|---|
| `INT` | 整数 | `1`、`42`、`-7` |
| `VARCHAR(50)` | 最多 50 个字符的短文本 | 姓名、手机号 |
| `TEXT` | 长文本 | 商品描述 |
| `DATE` / `DATETIME` | 日期 / 日期+时间 | `2026-10-13`、`2026-10-13 22:30:00` |
| `DECIMAL(10,2)` | 精确小数（**钱必须用它，不能用浮点数**） | `1999.00` |

**为什么必须声明？** 三个原因：
1. **省空间** —— 存 `42` 只需要几个字节，不用占一整块
2. **能校验** —— 往 `INT` 列塞 `"abc"` 会直接报错，而不是默默地存坏数据
3. **能计算/排序** —— 知道是数字才能求平均、知道是日期才能按时间排序

> **你这台机器的一个已知事实**：`sql_mode` 里包含 `STRICT_TRANS_TABLES`
> （来源：`D:\MySQL\MySQL Server 26.7\my.ini` 第 110 行）。
> 这就是"**严格模式**"—— 类型/长度不对**直接报错**，不会偷偷把 `"abc"` 变成 `0`。
> 这是好事，后面造数据时你会经常撞到它，届时不用惊讶。

## 0.5 主键：每张表的"身份证"

**主键（PRIMARY KEY）** 是一列（或几列组合），它必须满足两条：

1. **唯一** —— 不许有两条记录的主键相同
2. **不能空** —— 必须有值

**为什么需要它？**
- 能**精确定位**某一行：说"改 actor_id = 5 的那行"，谁都清楚是哪行
- **防止重复**：想插入两个 actor_id 都是 1 的演员，数据库会拒绝
- **让别的表能"指向"这一行**：比如"订单表"里存 `客户ID`，指向"客户表"的主键

**类比**：身份证号。一张没有主键的表，就像一叠**没编页码的纸**，你说"改第 3 张"，没人知道是哪张。

## 0.6 SQL 是什么？分几类？

**SQL** = 你用来跟数据库说话的**语言**。按用途分几类：

| 类别 | 干什么 | 关键词 | 危险度 |
|---|---|---|---|
| **DDL** 定义 | 建 / 改 / 删 **库和表**（改结构） | `CREATE` `ALTER` `DROP` | ⚠️⚠️ **高**（`DROP` 直接把表删没了） |
| **DML** 改数据 | 增 / 改 / 删 **行**（改内容） | `INSERT` `UPDATE` `DELETE` | ⚠️ **中高**（`DELETE` 忘了写条件会删光） |
| **DQL** 查询 | 只**查**，不改 | `SELECT` | ✅ 低（只读） |
| **DCL** 权限 | 授权 / 收权 | `GRANT` `REVOKE` | ⚠️⚠️ 高 |
| **元命令** | 看状态（不属于上面四类） | `SHOW` `DESC` `USE` `EXIT` | ✅ 低 |

**记忆法**：改**结构**的（DDL）最危险，改**内容**的（DML）次之，**只读**的（DQL）安全。

> 你之前跑的那条清点脚本，就是一堆 `SELECT`（DQL）+ 读 `performance_schema` 的表 —— 全是只读，所以我说"零风险"。

## 0.7 动手：用 6 条命令把上面全部亲眼看一遍

**先连上去**（这条你已经会了）：

```powershell
mysql -h 127.0.0.1 -P 3306 -u root -p
```

成功后会看到一个提示符 **`mysql>`** —— 表示"接下来的命令都发给 MySQL"。然后**一条一条敲**：

```sql
SHOW DATABASES;
USE sakila;
SHOW TABLES;
DESC actor;
SELECT * FROM actor LIMIT 5;
EXIT;
```

每条命令用到了哪条知识、你会看到什么：

| 命令 | 用到 | 你会看到 |
|---|---|---|
| `SHOW DATABASES;` | **0.3** 库 | 库的清单，和清点输出第 7 张表一样 |
| `USE sakila;` | **0.3** 库 | `Database changed` —— 表示"进到 sakila 这个库了"。**只切换，不改数据** |
| `SHOW TABLES;` | **0.3** 表 | sakila 里 23 张表的表名 |
| `DESC actor;` | **0.3 + 0.4** | `actor` 表的**表头**：每列叫什么、什么类型、是否允许空、是不是主键 |
| `SELECT * FROM actor LIMIT 5;` | **0.3 + 0.6** | 前 5 行数据。`*` = 所有列；`LIMIT 5` = 只要 5 行 |
| `EXIT;` | — | 退出客户端，回到 PowerShell |

**注意事项**
- 每条命令**结尾必须有分号 `;`** —— 这是告诉 MySQL"这条我说完了"。漏了它 MySQL 会等你继续输入（提示符变成 `->`，这时补一个 `;` 回车即可）。
- 全是**只读**操作，不会改动 `sakila` 的任何数据。
- 想看 MySQL 自己有哪些版本信息，可以在 `mysql>` 里敲 `SELECT VERSION();`。

**请把这 6 条的输出原样贴回来**（包括报错）。我会逐条告诉你看到了什么、说明什么。

## 本课术语小抄

| 词 | 一句话解释 |
|---|---|
| 数据库（广义） | 有规矩、能多人同时用、坏了能恢复的数据仓库 |
| 服务器 / server | 常驻后台、真正存数据的那个程序（你这台叫 `MySQL267`） |
| 客户端 / client | 你敲命令的小工具，负责传话（`mysql.exe`） |
| 库 / database / schema | 一套业务的容器 |
| 表 / table | 一类东西的清单，二维表格 |
| 列 / column / 字段 | 表头，一个属性，有数据类型 |
| 行 / row / 记录 | 表里的一条具体数据 |
| 主键 / primary key | 每行的"身份证"：唯一、不能空 |
| 数据类型 | 这一列存什么（INT / VARCHAR / DATE / DECIMAL…） |
| SQL | 跟数据库说话的语言，分 DDL/DML/DQL/DCL |
| 端口 / port | 一台机器上区分不同服务的"门牌号"，MySQL 默认 3306 |
| 严格模式 | 类型/长度不合法直接报错，不偷偷改数据 |

## U0 实测复盘（2026-10-14，你的真实输出）

原始记录：`sql/U0_return.txt`。**6 条命令一次全通过，零报错。**

### 1. `show databases;` → 7 个库（0.009 秒）

**互相印证**：这和你做环境清点时输出第 7 张表（库表排行）是**同一批库** —— 两个独立来源对上了。
这就是我们后面每一步都要做的事：**用第二个来源验证第一个**。

顺带第一次见到"性能"：`0.009 sec` 是 MySQL 报的**这条命令花了多久**。以后你天天要盯这个数字。

### 2. `use sakila;` → `Database changed`

这句话是**客户端**回的，不是服务器。它等于说：
"记住了，接下来我发给服务器的命令都自动带上 `sakila` 这个前缀。"

—— 所以后面 `show tables`、`desc actor` 都不用再写库名。

### 3. `show tables;` → 23 张表（0.012 秒）

**表名就是业务地图**。`sakila` 是一家 DVD 出租店：

| 表名 | 业务含义 |
|---|---|
| `actor` | 演员 |
| `film` | 影片 |
| `customer` | 客户 |
| `rental` | 租借记录 |
| `payment` | 付款 |
| `store` / `staff` | 门店 / 员工 |
| `inventory` | 库存 |
| `film_actor` | **影片 ↔ 演员 的对应关系** |

两个值得记一笔的点：

- ⚠️ 这 23 行里**混着几个"视图（view）"** —— 长得像表，实际是"存起来的查询"。以后单独讲。
- `film_actor` 这种"两边都存对方 ID"的表叫**连接表**，用来表达"一部电影多个演员、一个演员多部电影"的
  **多对多关系**。设计自己的库时会用到它。

### 4. `desc actor;` → 本课信息量最大的一条

`desc` 是 `DESCRIBE` 的缩写，意思是"把这张表的**表头定义**给我看"。
**它返回 4 行，是因为 `actor` 表正好有 4 列** —— 它把"每一列"当成"一条记录"来展示。

| 显示的表头 | 含义 | `actor` 表里的值 |
|---|---|---|
| `Field` | 列名 | `actor_id` / `first_name` / `last_name` / `last_update` |
| `Type` | **数据类型**（U0.4） | `smallint unsigned` / `varchar(45)` / `timestamp` |
| `Null` | 允许空吗（`NO` = 必填） | 四列全是 `NO` |
| `Key` | **键**：`PRI`=主键，`MUL`=有普通索引 | `actor_id` = `PRI`；`last_name` = `MUL` |
| `Default` | 不填时用什么默认值 | 两列显示 `NULL` |
| `Extra` | 额外自动行为 | 见下 |

**逐项拆开讲：**

- `smallint unsigned`：占 2 字节的整数，`unsigned` = 不许负数，所以范围是 **0 ～ 65535**。
- `varchar(45)`：最多 45 个字符的文本。为什么是 45？够用就行 —— 类型选窄一点更省空间。
- `Null = NO`：这四列**都是必填**，插入时不写会报错。
  > 小坑：`Default` 那列显示 `NULL`，**不代表允许存 NULL**。因为 `Null=NO`，
  > 这里的 `NULL` 实际意思是"**没有默认值**"，插入时必须自己给。
- `Key = PRI`：**`actor_id` 是主键** —— 这就是 U0.5 讲的东西，现在你亲眼看到了。
- `Key = MUL`：`last_name` 上有一个**允许重复的索引**。
  > 👉 **这两格（`PRI` / `MUL`）就是下一课 U1 的全部内容。**
- `Extra = auto_increment`：`actor_id` **自动递增**。你插入新演员时不用自己编 ID，
  MySQL 自动给下一个号（1、2、3……）。
- `Extra = DEFAULT_GENERATED on update CURRENT_TIMESTAMP`：`last_update` 会在
  **插入时自动填当前时间、之后每次改动也自动刷新**。所以这列你永远不用手动写。

### 5. `select * from actor limit 5;` → 数据与表头完全对上

- `5 rows in set` —— `LIMIT 5` 真的只要了 5 行。
- `actor_id` 是 **1、2、3、4、5** 连着排 —— 这正是 `auto_increment` 在起作用。
- `last_update` 五行**全是同一秒** `2006-02-15 04:34:33` —— 因为这是官方示例数据，
  一次性导入的，不是人工一条条录的。**真实业务库不会长这样**（这正好是实2 造数时要模仿的）。

U0 的四个核心概念，在你的真实输出里**全部落地**了：

| 概念 | 在输出里的位置 |
