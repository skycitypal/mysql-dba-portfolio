## 为什么这样安排顺序

先把**概念地基**打牢，再动手操作；每个实操步骤都标注「用到哪条知识」。

顺序：数据库基础 → 索引 → InnoDB 怎么存数据 → 慢查询诊断 → 运维视角 → **然后才**建库、造数、调优。

理由：DBA 的活不是"会敲 SQL"，而是**知道每个数字意味着什么、能判断它是好是坏**。
比如"缓存命中率 96%"这个数字本身没有意义 —— 要先知道实例有没有负载，才知道它算不算问题。
