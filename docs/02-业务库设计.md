# 02 · 业务库设计

实操 1 的产出说明：业务场景、表清单，以及所有业务表都要遵守的字段与命名规范。

---

## 业务场景

一个小型电商订单系统。

选这个场景的理由：订单、订单明细、支付三张表基本能覆盖真实建模里最常见的问题 ——
一张主表、一张明细表、一张状态会反复流转的支付表，再加上客户和商品两个基础数据表。
数据量也容易造，适合后面做索引对比。

## 表清单

| 表名 | 一行代表什么 | 作用 |
|---|---|---|
| `t_customer` | 一个客户 | 下单的人 |
| `t_product` | 一个商品 | 卖的东西 |
| `t_order` | 一次下单 | 订单头，记录谁、什么时候下单、总共多少钱 |
| `t_order_item` | 订单里的一行商品 | 订单明细。一次买三种东西就有三行 |
| `t_payment` | 一次支付 | 一个订单可能有多条：失败重试、分次支付 |

数据量预期：`t_order_item` 会是最大的表，目标是十万行以上，用来做索引前后的对比。

---

## 通用规范

下面这些是所有业务表都要遵守的，写第一张表时就按这个来。

### 固定字段

| 字段名 | 类型 | 说明 |
|---|---|---|
| `id` | `bigint` | 主键。数据库内部使用的流水号 |
| `deleted` | `tinyint NOT NULL DEFAULT 0` | 软删标记。`0` 未删除，`1` 已删除 |
| `create_time` | `timestamp(6) NOT NULL` | 创建时间 |
| `update_time` | `timestamp(6) NOT NULL` | 更新时间，改动时自动刷新 |

**为什么用软删而不是 `DELETE`**：删掉的数据还能恢复，也留下审计痕迹。
代价是每个查询都要带上 `deleted = 0`，这一点在后面的索引设计里要一起考虑。

**为什么时间字段用 `timestamp(6)`**：带六位小数秒（微秒）。同一秒内发生多条记录时，
带上微秒才能排出先后顺序。

### 业务唯一标识

`id` 是数据库自己用的流水号，不适合对外。涉及外部系统对接、或者需要防重的表，
再加一列业务单号，例如 `order_id`、`payment_id`，类型 `varchar(64)`，并加**唯一索引**。

作用是让数据库兜底防重：应用层万一重复提交，唯一索引会直接拒绝，而不是写进两条脏数据。

### 命名约定

| 对象 | 约定 | 例子 |
|---|---|---|
| 表名 | `t_` + 业务模块 | `t_order`、`t_order_item` |
| 主键 | 统一叫 `id` | — |
| 唯一索引 | `uk_` 开头 | `uk_order_id` |
| 普通索引 | `idx_` 开头 | `idx_customer_ct` |

### 两条说明

**关于主键用不用自增**：本项目用 `bigint` + `AUTO_INCREMENT`，单机系统这样最省事。
分布式系统一般会换成雪花 ID 之类的方案，避免多库自增冲突 —— 这点记在这里，本项目不采用。

**关于 `USING BTREE`**：很多建表模板会在索引后面显式写它。InnoDB 的索引默认就是 BTREE，
本项目不重复写。

## 第一张表：`t_customer`

固定字段先给出，业务字段待补：

```sql
CREATE TABLE `t_customer` (
  `id` bigint NOT NULL AUTO_INCREMENT COMMENT '主键 ID',

  -- 业务字段待补，建议至少包含：
  --   客户登录名（或手机号）
  --   昵称
  --   邮箱
  --   状态

  `deleted` tinyint NOT NULL DEFAULT 0 COMMENT '删除标记: 0-未删除, 1-已删除',
  `create_time` timestamp(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) COMMENT '创建时间',
  `update_time` timestamp(6) NOT NULL DEFAULT CURRENT_TIMESTAMP(6) ON UPDATE CURRENT_TIMESTAMP(6) COMMENT '更新时间',

  PRIMARY KEY (`id`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='客户表';
```

**待定项**：

- 业务字段选哪几个，各用什么数据类型
- 哪一个字段需要加唯一索引（也就是「同一个客户不允许重复」靠哪一列来保证）
